验证日期：2026-11-20。运行环境：ljh3 的 `retail` Python 环境。Qdrant 为本机 `127.0.0.1:6333`。

## 交付内容

- 新增 `review` 命令和服务 `case_review` 模式，关联平台、店铺、订单、退款与凭证。
- 实现记录一致性、实付金额、运费依据和材料四类核查；每个发现包含记录证据、适用政策引用或明确的数据/知识/工具缺口。
- 记录重复与实际重复付款分别处理，合法分次退款不标为重复；仅汇总唯一退款 ID 的成功状态记录，不用商品原价代替实付金额。
- 已审核政策适配规则绑定正文、版本、URL、来源类型、平台与渠道。政策变化时停止套用旧规则；来源批准清单不由案例生成脚本自动刷新。
- 模型只起草解释，不改变检查结果。引用、付款动作表述及检查状态矛盾会触发回退；纯知识/工具缺口直接输出结构化处理要求。

组合流程匹配 60/60 预期结果：21 个本次检查未见异常、27 个需人工复核、6 个待补信息、3 个待补政策、3 个待补工具。27 个标注异常全部检出，21 个正常案例未出现异常误报；引用 ID 与范围校验未发现错误。

这组对照展示数据工具与政策适配核查的互补覆盖，属于合成案例的机制验收，不表示真实业务准确率或人工效率收益。完整结果、分组与 Trace 在 `evaluation.json`。

## 真实模型与服务联调

8 个演示案例使用真实 DeepSeek 接口与 Qdrant 完成联调，结构化核查结果 8/8 匹配预期。其中 2 个纯知识/工具缺口直接输出处理要求；其余 6 个进行模型说明，最终 6 份草稿通过引用和状态校验，最终运行没有草稿回退。人工复核了六份草稿的数据金额、政策引用和结果范围，记录在 `manual-review.json`。

模型调用与结果不用于修改核查标签或执行退款。真实模型只接收人工构造案例中的结构化事实及已审核公开政策。调用量与 Token Usage 见 `model-synthetic.json`。

初期试验发现模型会把未完成检查描述为未发现异常、把核查通过描述为审批通过，或重复无关的政策条件。改进包括传递检查项及实际使用的条件、显式引用白名单、草稿状态校验、纯缺口免模型分流。试验输出保留为 `model-synthetic-initial.json`、`model-synthetic-before-guard.json`、`model-synthetic-guard-trial.json`、`model-synthetic-reference-trial.json`，最终结果以 `model-synthetic.json` 为准。

`service-qdrant.json` 验证真实后端下的四个案例结果，包含金额异常、运费承担方不一致、政策缺口与工具缺口；任务完成，案例状态正确，SSE 正常结束。
