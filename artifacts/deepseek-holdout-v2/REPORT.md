# RetailOps Agent 冻结独立集实验

实验日期：2026-11-03  
运行环境：`ljh3`、Conda `retail`、Python 3.12.16  
模型：`deepseek-flash`，非思考模式  
Harness² 预算：顺序模式、每项 `k=1`

## 评测设计

测试集包含 8 项合成经营分析任务，退款率、品类退款分摊、组合指标和每日汇总各 2 项。不同样例随机变化订单数、订单行数、品类、数量、价格、日期、退款订单和同订单多次退款，并使用多种自然语言任务表述。

每项任务包含生成器单独计算的 `expected.json`。最终输出既要通过项目业务校验器，也要与外部真值逐字段一致。`manifest.json` 记录 32 个数据/真值文件和 14 个冻结源码文件的 SHA-256；本地与服务器校验均为 `mismatches=0`。

## 先诊断，再冻结

第一套 `holdout-v1` 初测时，规则修复虽然通过内部校验 8/8，但外部真值只通过 4/8。原因是规划器没有识别“退款订单占比”等表述，并把“类别净销售额”错误识别为每日汇总。

修复意图识别并增加 4 项规划器回归测试后，`holdout-v1` 外部真值恢复为 8/8。随后使用不同随机种子和多种任务表述生成 `holdout-v2`，记录核心源码哈希；生成后未再修改核心代码。

## 最终结果

| 评测 | 基础/朴素策略 | 最终策略 | 外部真值 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 确定性校验修复 | 2/8 | 8/8 | 8/8 | 6 项修复，2 项无需修复 |
| DeepSeek + Harness² | 2/8 | 8/8 | 8/8 | 6 项改进，2 项保留正确基础，0 回归 |

真实模型运行指标：

- 32 次策略执行；
- 30 次 API 请求，平均每项 3.75 次；
- 102,753 input tokens、4,099 output tokens，共 106,852 tokens；
- 平均每项 13,356.5 tokens；
- 6 次 JSON Output 失败后自动降级为普通文本解析；
- 8 项最终校验问题均为 0。

## 结论边界

结果证明当前实现能在这 8 项冻结合成任务上识别需要修复与无需修复的情况，并通过确定性复验和外部真值检查。测试规模仍小，且数据是合成的；不能据此宣称对真实企业数据、开放域任务或任意经营口径具有 100% 泛化能力。后续应加入真实脱敏数据、异常退款、缺失字段、极端金额和更大规模任务集。
